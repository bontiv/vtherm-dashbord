## Notes d'application
- 1.1 : `narrow` est déclaré dans une interface `DisplayProps` ajoutée aux propriétés des composants de chaque hook, et non dans `BaseProps`, que les contextes de visibilité réutilisent : les conditions de visibilité et les tests des plugins n'ont pas à le fournir.
- 3.1 : le panneau ne recevait pas de hauteur définie de Home Assistant (`height: 100%` donnait la hauteur du contenu) ; il prend maintenant la hauteur de la fenêtre (`100vh`, puis `100dvh`), ce qui fait aller le tiroir et la barre d'enregistrement jusqu'en bas de l'écran.
- 4.2 : les cases des onglets de configuration gardent leur `label for` (équivalent pour le toucher et l'accessibilité) au lieu d'être enveloppées ; le libellé porte la classe `touch-target`.
- 4.3 : `frontend/preview/mobile-check.ts` ne signale rien à 360 et 375 px sur les pages natives, les huit sections de la configuration générale et le détail d'un complément. La configuration d'un thermostat n'a pas pu être mesurée : l'instance de développement n'a que la configuration centrale.
- 5.2 : `npm run check` ne signale que l'ancien R0903 de `complements.py` ; `npm test` n'échoue que par des délais dépassés sous la charge du conteneur (`docs.test.ts`, `native-docs.test.ts`, qui passent seuls) ; `pytest` échoue sur `test_register_ui_plugin_example`, sans lien avec ce change : `vtherm_api` (commit `e8a5d98`) accepte maintenant une déclaration identique, que l'exemple de la documentation attend refusée.
- 5.1 : essai fait par l'utilisateur dans l'application Home Assistant sur son téléphone, sans problème signalé ; modèle et version de l'application non communiqués.
